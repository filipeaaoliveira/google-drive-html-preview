# Chrome Web Store submission

**Visibility:** Unlisted — installable only via a direct link. Works on Chrome
and on Brave, which installs from the same store.

## Single purpose

Render HTML files stored in Google Drive as web pages instead of displaying
their source code.

## Permission justifications

The full permission set is `storage` plus two host permissions. There are no
others.

**storage** — The extension passes a file's downloaded contents from its
service worker to its viewer page through `chrome.storage.session` under a
single-use key that is deleted on read. It also stores one boolean in
`chrome.storage.local` recording whether the user has turned previewing off.

**Host permission: `https://drive.google.com/*`** — A content script runs on
Drive to detect that the user has opened a file whose name ends in `.html` or
`.htm`, and to navigate to the extension's viewer. The script matches the whole
Drive origin rather than only file-view URLs because Drive is a single-page
application: it changes the visible file without a full page load, and matching
the origin is what lets the content script follow those in-page navigations
without requesting the `webNavigation` permission.

**Host permission: `https://drive.usercontent.google.com/*`** — This is the
endpoint that serves Drive file contents. The extension fetches the opened
file's bytes from it using the user's existing session cookies, which is why
the extension requires no OAuth scopes and shows no consent screen.

## Are you using remote code?

No. All of the extension's own code is included in the package; extension pages
run under `script-src 'self'` with no inline scripts.

The extension does render documents that may themselves reference scripts or
stylesheets from public CDNs — that is inherent to displaying an HTML file, and
those resources belong to the user's own document, not to the extension. Such
documents are rendered in a frame declared under the manifest's `sandbox` key,
which places them in an opaque origin with no access to `chrome.*` APIs, to
extension storage, or to the user's cookies. This is the mechanism Chrome
documents for rendering untrusted content in an extension.

## Package to upload

Run `npm run package`. It writes `dist/drive-html-preview-<version>.zip`
containing only `manifest.json`, `icons/`, and `src/` — the extension's runtime
files and nothing else.

That zip is what gets uploaded. Do **not** zip the repository root: it carries
`spike/` (which holds a second `manifest.json`), `test/`, `tools/`, `docs/`,
and internal engineering notes, all of which a reviewer would see.

## Listing copy

**Privacy policy URL:** https://filipeaaoliveira.github.io/google-drive-html-preview/PRIVACY.html

**Short description** (92/132 characters):

> Renders HTML files stored in Google Drive as web pages instead of showing their source code.

**Detailed description:**

> Google Drive shows HTML files as source code. There is no setting that changes
> this — Drive's own web hosting was retired in 2016 — so a file you open in Drive
> is a wall of markup instead of the page it describes.
>
> Drive HTML Preview renders it instead. Open an HTML file in Drive and you get the
> page, full screen, with a toolbar to switch back to the source or return to your
> folder.
>
> How it works
>
> The extension uses the Google session you are already signed in to. It asks for no
> OAuth scopes, shows no consent screen, and has no server: your file is downloaded
> by your own browser and rendered locally. Nothing is transmitted anywhere, and
> there is no analytics or telemetry of any kind.
>
> Your file is rendered inside a sandboxed frame with its own opaque origin, so the
> document cannot reach the extension's APIs, its storage, or your cookies.
>
> Scope
>
> Files are expected to be self-contained — everything inline, or loaded from public
> CDNs. HTML that references sibling files in the same Drive folder for CSS,
> JavaScript or images will not resolve them.
>
> Permissions
>
> Storage, plus access to drive.google.com and drive.usercontent.google.com. Nothing
> else. Each is justified in the repository's store listing notes.
